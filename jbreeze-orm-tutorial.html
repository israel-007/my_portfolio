Eloquent-Style ORM

JBreeze ORM

A fluent, schema-validated ORM for JSON data. Built on top of JBreeze, it adds model-based querying, automatic validation, and structured data management with an elegant API.

Get Started GitHub Repository
00 / Overview

Why JBreeze ORM?

Model-Based Queries

Define models with schemas and query them using a fluent API similar to Eloquent.

Schema Validation

Automatic validation of data types, required fields, allowed values, and more.

Nested Fields

Support for deeply nested data using dot notation (address.city, meta.tags).

Remote & Local

Load JSON from files or remote URLs. Works with any JSON source.

01 / Getting Started

Setup & Configuration

Installation

Install via Composer (same as JBreeze):

bash
composer require jbreeze/jbreeze

Project Structure

Organize your project with dedicated folders for models and JSON files:

bash
project/
├── models/ # Your model classes
│ └── Users.php
├── tables/ # JSON data files
│ └── users.json
└── app.php

Initialize Registry

In your main application file, initialize the Registry with your custom folders:

php
require 'vendor/autoload.php';
use Registry\Registry;
Registry::initTables(
  __DIR__ . '/models',
  __DIR__ . '/tables'
);
Result
Registry initialized.
Models folder: ./models
Tables folder: ./tables

Define a Model (Users.php)

Create a model class with schema validation:

php
namespace App\Models;
use JB_Model\JB_Model;
class Users extends JB_Model
{
  protected static $tableName = "users";
  public static $schema = [
    'id' => ['type' => 'int', 'primary_key' => true],
    'name' => ['type' => 'str', 'required' => true],
    'email' => ['type' => 'str', 'required' => true],
    'age' => ['type' => 'int'],
    'created_at' => ['type' => 'mixed', 'default' => 'NOW()']
  ];
}
Schema Applied
id: auto-incremented integer
name: required string
email: required string
age: optional integer
created_at: timestamp (default)

Validation enabled

Create JSON Data File

Create tables/users.json with sample data:

json
[
  {
    "id": 1,
    "name": "Alice",
    "email": "alice@example.com",
    "age": 28,
    "created_at": "2024-01-15"
  }
]

Find by ID

Retrieve a single user by their ID.

php

03 / Schema Validation

Data Types & Rules

JBreeze ORM enforces schema validation on all operations. Define rules once, and they're applied automatically.

Type Validation

Ensure fields match expected data types:

Type Description Example
int Integer (whole numbers) 'age' => ['type' => 'int']
str String (text) 'name' => ['type' => 'str']
bool Boolean (true/false) 'is_active' => ['type' => 'bool']
float / double Floating-point number 'price' => ['type' => 'float']
array Array of values 'tags' => ['type' => 'array']
object Object/JSON object 'metadata' => ['type' => 'object']
mixed Any type 'created_at' => ['type' => 'mixed']

Other Validation Rules

Rule Description Example
required Field must be provided 'email' => ['type' => 'str', 'required' => true]
allowed Restrict to specific values (pipe-separated) 'status' => ['type' => 'str', 'allowed' => 'active|inactive|pending']
length Max string length 'username' => ['type' => 'str', 'length' => 20]
default Default value if missing 'role' => ['type' => 'str', 'default' => 'user']
default => 'NOW()' Auto-timestamp 'created_at' => ['type' => 'mixed', 'default' => 'NOW()']
primary_key Auto-increment ID 'id' => ['type' => 'int', 'primary_key' => true]

Complete Schema Example

php
public static $schema = [
  'id' => ['type' => 'int', 'primary_key' => true],
  'name' => ['type' => 'str', 'required' => true],
  'email' => ['type' => 'str', 'required' => true, 'length' => 100],
  'age' => ['type' => 'int'],
  'status' => ['type' => 'str', 'default' => 'active', 'allowed' => 'active|inactive|pending'],
  'address.country' => ['type' => 'str', 'required' => true],
  'address.city' => ['type' => 'str'],
  'created_at' => ['type' => 'mixed', 'default' => 'NOW()']
];

04 / Advanced Features

Backup, Restore & More

Backup & Restore

Automatically backup your JSON data and restore when needed.

php
// Create automatic backup
Users::backupJsonFile();
Result
Backup created
File: backup_users.json
Location: tables/backup/
php
// View backup contents
print_r(Users::getBackup());
Result
Array of all records
from backup_users.json
php
// Restore from backup
Users::restoreFromBackup();
Result
Backup restored
users.json replaced with
contents from backup

Update Structure

Enforce schema rules on existing data and rename fields.

php
// Clean & normalize all records
Users::updateStructure();
Actions
✓ Removes extra fields
✓ Adds missing fields
✓ Fills defaults
✓ Auto backup created
php
// Rename fields
Users::updateStructure([
  'mobile' => 'phone',
  'address.county' => 'address.state'
]);
Result
✓ 'mobile' → 'phone'
✓ 'address.county' → 'address.state'
All records updated
Backup created

$users = RemoteUsers::select()

05 / Best Practices

Workflow Tips

Define Clear Schemas

Always define a complete schema. It's the foundation for data integrity.

Use Required Fields

Mark critical fields as 'required' to catch missing data early.

Backup Before Restructuring

Automatic backups are created, but always review before running updateStructure().

Chain Methods Efficiently

Combine where(), order(), limit() to reduce code and improve readability.
